# Decision Log

## Decided

| # | Decision | Options considered | Chosen | Rationale | Date |
|---|---|---|---|---|---|
| D-001 | Add `/functions` directory for Azure Function | Keep in `/api`, separate `/functions` | Separate `/functions` | The Azure Function is a distinct deployment unit (Python, not Go) with its own `host.json` and function bindings. Keeping it separate from the Go API avoids confusion. | 2026-10-03 |
| D-002 | Add `/db` directory for shared migrations | Keep migrations in `/api`, separate `/db` | Separate `/db` | Migrations are shared across the API and worker (both read/write the database). A shared `/db/migrations/` directory makes this explicit and avoids duplicating schema definitions. | 2026-10-03 |
| D-003 | Azure Function language (formerly O-001) | **A)** Python<br>**B)** JavaScript/TypeScript<br>**C)** C# | **A) Python** | The worker service is already implemented in Python. Using Python for the Azure Function minimizes context-switching, shares Azure SDK patterns, and allows common data parsing/validation libraries across worker and trigger code. | 2026-10-03 |
| D-004 | Document Intelligence custom model type (formerly O-002) | **A)** Custom template model<br>**B)** Custom neural model | **A) Custom template model (with neural evaluation fallback)** | Academic degrees and marks sheets follow structured institutional layouts. Custom template models require fewer training samples (minimum 5 documents), offer lower inference latency/cost, and provide higher geometric field alignment accuracy for tabular grade data. | 2026-10-03 |
| D-005 | SAS token type for browser upload (formerly O-003) | **A)** User-delegation SAS<br>**B)** Account-key SAS | **A) User-delegation SAS** | Best-practice cloud security: signed dynamically via Entra ID user-delegation key using the Go API container app's managed identity. Eliminates storage account key storage and rotation overhead. | 2026-10-03 |
| D-006 | PostgreSQL authentication method (formerly O-004) | **A)** Entra token only<br>**B)** Password stored in Key Vault only<br>**C)** Entra token primary with Key Vault fallback | **C) Entra token primary with Key Vault password fallback** | Managed identity Entra tokens are used in Azure deployed environments; password credentials (stored in Key Vault for cloud, and `.env` for local Docker) are maintained for local developer tooling and resilient fallback. | 2026-10-03 |
| D-007 | Local queue strategy for development (formerly O-005) | **A)** Small queue interface with local in-memory fake<br>**B)** Full Service Bus emulator | **A) Interface with local fake** | Keeps local development via `docker compose` lightweight, fast, and dependency-free. A clean Go/Python queue interface abstraction allows transparently switching between the local fake and Azure Service Bus. | 2026-10-03 |
| D-008 | Failed-job handling & dead-letter mechanism (formerly O-006) | **A)** Scheduled polling Function<br>**B)** Worker-only status update<br>**C)** DLQ trigger Function with worker update | **C) DLQ trigger Function with worker inline failure handling** | The worker catches fatal processing errors immediately, marks `jobs.status = 'failed'`, and completes the message. If a transient error exhausts max delivery attempts (5), a dead-letter queue trigger Function updates the job status to `failed` and alerts operators. | 2026-10-03 |
| D-009 | CORS configuration for Blob direct upload (formerly O-007) | **A)** Configure CORS on Azure Storage Account<br>**B)** Proxy uploads through API | **A) Storage Account CORS** | Configured directly on Blob Storage via Bicep to permit `PUT` and `OPTIONS` from the frontend domain. Maintains zero-hop direct client upload architecture without saturating API bandwidth. | 2026-10-03 |
| D-010 | Container Apps image deployment strategy (formerly O-008) | **A)** Bicep parameter (`apiImageTag`, `workerImageTag`)<br>**B)** CLI `az containerapp update` | **A) Bicep parameters** | Declarative infrastructure-as-code ensures complete reproducibility, auditability, and zero configuration drift between git commits and Azure runtime environment. | 2026-10-03 |
| D-011 | Include `degree` in records schema (formerly P-003) | **A)** Derive from document type<br>**B)** Add `degree` column to `records` table | **B) Add `degree TEXT` column to `records`** | The public verification screen explicitly requires displaying `degree`. Adding a dedicated column to `records` matches the requirements cleanly without runtime JSON extraction ambiguities. | 2026-10-03 |
| D-012 | Two-Pass Bicep deployment workflow | **A)** Single Bicep pass with placeholder images<br>**B)** Two-pass Bicep workflow (Pass 1 Core Infra, Pass 2 Apps) | **B) Two-pass Bicep workflow** | Solves the circular dependency where Container Apps require an image that cannot be pushed to ACR until ACR has been provisioned. Pass 1 creates ACR/Infra, images are pushed with the commit SHA, and Pass 2 deploys apps with image tag parameters. | 2026-10-03 |
| D-013 | Dedicated container for stamped certificates | **A)** Store stamped PDFs in `raw-uploads`<br>**B)** Dedicated `stamped-documents` container | **B) Dedicated `stamped-documents` container** | Event Grid watches `raw-uploads` for new uploads. Storing output stamped certificates in `raw-uploads` would trigger recursive Function executions. A separate container isolates output artifacts. | 2026-10-03 |
| D-014 | Temporary Read-SAS for review screen preview | **A)** Permanent public read access<br>**B)** Dynamic 15-minute read SAS generated by API | **B) Dynamic 15-minute read SAS** | The review screen requires rendering the source scan side-by-side with extracted fields. Generating a short-lived user-delegation read SAS URL on `GET /api/v1/review/:jobId` preserves privacy and zero-trust storage isolation. | 2026-10-03 |
| D-015 | Internal API authentication | **A)** Open internal port<br>**B)** Header `X-Internal-Secret` + internal virtual network ingress | **B) Header secret + internal virtual network ingress** | Secures worker-to-API status notifications while maintaining simple configuration across container environments and local development. | 2026-10-03 |
| D-016 | Deterministic canonical JSON normalization | **A)** Standard JSON serialization<br>**B)** Canonical JSON with Unicode NFC, whitespace collapsing, and string decimals | **B) Canonical JSON with NFC, whitespace collapsing, string decimals** | Floating point variances between Go (`float64`) and Python (`float`), alongside Unicode and whitespace variations, cause cryptographic hash mismatches. String decimals and NFC normalization guarantee bit-for-bit identical hashes. | 2026-10-03 |
| D-017 | Two-tier failure completion protocol | **A)** Always dead-letter on any error<br>**B)** Worker completes fatal errors; DLQ catches exhausted transient retries | **B) Worker completes fatal errors; DLQ catches exhausted retries** | Corrupt files or schema mismatches will never succeed on retry; retrying them wastes queue and compute budget. Only transient infrastructure errors are abandoned for retry. | 2026-10-03 |
| D-018 | Just-In-Time (JIT) user provisioning | **A)** Manual admin pre-seeding of `users`<br>**B)** JIT provisioning in API auth middleware via Entra ID claims | **B) JIT provisioning via Entra ID claims** | Avoids fragile manual onboarding sync. Authenticated users are automatically provisioned or updated on first request, satisfying foreign key constraints on `jobs.uploader_id`. | 2026-10-03 |
| D-019 | Tabular marks confidence evaluation | **A)** Average confidence across table<br>**B)** Per-cell confidence check against `CONFIDENCE_THRESHOLD` | **B) Per-cell confidence check** | A transcript with 10 high-confidence subjects and 1 misread grade must not be trusted silently. Any single sub-threshold cell correctly triggers human review. | 2026-10-03 |
| D-020 | Issuer upload rejection action | **A)** Delete job from database<br>**B)** Transition status to `failed` with audit reason | **B) Transition to `failed` with audit reason** | Allows issuers to reject unreadable or fraudulent documents with an explanation while preserving an audit trail for the student and institution. | 2026-10-03 |
